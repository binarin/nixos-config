* Problem

pgtk emacs has problems being run as a daemon do to idiosyncrasies van
wayland/pgtk implementation. As an alternative, `emacs-lock-mode` is
used on a bunch of important buffers, making accidental exit impossible.

There were a few attempts already to do this (see git history), but
the remaining quirk is still there: pressing 'S-q' (niri keybinding
for closing windows) incorrectly triggers emacs-lock-mode protection
with only one remaining emacs frame on active niri workspaces. In that
case emacs-niri-awareness extended behaviour of `frame-visible-p` is
playing a bad joke with us.

* Conclusion

~emacs-niri-awareness~ pinned to stale commit, the fix itself was sound. Solved by

#+begin_src sh
  nix flake update emacs-niri-awareness
#+end_src
