* Goal (2026-11-09)
Advance the =swan-lake-current= fork pins used by zwanenzang (consumed via
common) and propagate the resulting revisions through
zwanenzang -> common -> swan-lake / nixos-config. Pins may be bumped directly.

* Chain
- Fork branches (GitHub =binarin=) consumed as =github:binarin/<repo>/swan-lake-current[/<branch>]=:
  nixpkgs, flake-parts, import-tree, disko, home-manager, sops-nix,
  emacs-overlay, llm-agents.nix, emacs-tramp-rpc.
- zwanenzang flake.lock pins flake-parts / nixpkgs / nixpkgs-unstable /
  import-tree.
- common flake.lock pins those plus disko / home-manager / sops-nix /

  =swan-lake-current=.
- swan-lake and nixos-config pin =common/swan-lake-current=.

* Plan (revised)
Operator clarified after the first attempt: do not advance the fork
=swan-lake-current= branches (nixpkgs in particular). Only move the
zwanenzang -> common link, then the common pin in nixos-config.
1. Pull each master in the umbrella clones before pinning.
2. In common: =nix flake update zwanenzang=, verify, commit, push master,
   fast-forward =swan-lake-current= to it.
3. In nixos-config: =nix flake update common=, verify, commit, push.
4. All fork branches stay untouched.
5. Follow-up (same session, operator approved): bump the common pin in
   swan-lake as well.

** Operator script
- Added =swan-lake-common/scripts/relock-chain.py= (common master 0ffc6b2):
  walks zwanenzang -> common -> swan-lake / nixos-config, fetch+ff each
  master, relocks the upstream pin, verifies with =nix flake check
  --no-build=, commits flake.lock, pushes master, promotes
  =swan-lake-current= and waits for the GitHub mirror before relocking
  consumers. It refuses dirty/ahead/detached checkouts, non-canonical
  consumer declarations, mismatched locked revisions and non-fast-forward
  promotions; it never force-pushes. =--dry-run= prints the plan, an
  idempotent rerun is a no-op.
- =swan-lake-common/scripts/test-relock-chain.py= covers it with four
  throwaway git+file repos and local bare origins: bump propagation,
  promotion, idempotent rerun, dirty-checkout abort.
- Verified the real chain with =--dry-run= and a live no-op run (all pins
  already current; no commits). common master now has the script while
  =swan-lake-current= deliberately stays at the promoted pin ccc54a7, so
  consumers are not re-pinned for a tooling-only change.
