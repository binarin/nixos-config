#+title: Paseo daemon on zeroclaw

* Context
zeroclaw is a headless guest VM used as a remote dev box for AI coding
agents. Paseo (https://paseo.sh, AGPL) is a self-hosted daemon + CLI for
driving agents remotely (mobile/web client via relay). The desktop
(Electron) package exists in llm-agents.nix as =paseo-desktop=, but the
headless daemon + CLI package only exists upstream, so both were vendored
into this repo rather than adding a new flake input.

* What was done (2026-10-16)
- [X] Vendor upstream daemon package =nix/package.nix@v0.11.4= into
      =modules/packages/paseo.nix= (fetchFromGitHub source, pinned
      version + hashes, overlay =self.overlays.paseo= added to
      =defaultOverlays= in =modules/nix.nix=).
- [X] Vendor upstream NixOS module =nix/module.nix@v0.11.4= into
      =modules/services/paseo.nix= (dropped the =allowedHosts= rename

- [X] Enable on zeroclaw as user/group =binarin=:

      relay enabled (hosted app.paseo.sh), service PATH inherits
      binarin's profiles so spawned agents find =pi= etc.
- [X] Dropped the dangling =llm-agents.paseo= attr from zeroclaw's

- [X] Built =packages.x86_64-linux.paseo= and the zeroclaw toplevel;
      CLI reports 0.11.4.

* npmDepsHash note
Our nixpkgs pin (nixos-26.05, e4bae1bd) ships a fetcher-v1
=fetchNpmDeps= whose Rust implementation differs from upstream's pin
(nixos-unstable, 9dcb002c), so upstream's =nix/npm-deps.hash= does not
match. To update the version: bump =version=, refresh the =src= hash,
temporarily keep the old =npmDepsHash=, build
=nix build .#packages.x86_64-linux.paseo= and replace it with the
"got:" hash from the fixed-output-derivation mismatch error.

* Web UI auth via mandatory clan vars (2026-11-07)
- =services.paseo= now declares a =paseo-auth= clan var generator whenever
  it is enabled. Files: =password= (operator-readable copy) and =env=
  (=PASEO_PASSWORD=...=, consumed by systemd =EnvironmentFile=).
- The daemon reads =PASEO_PASSWORD= and bcrypt-hashes it at startup, so the
  clan var holds plaintext and never needs a precomputed hash.
- Enabling =services.paseo= on a machine without clan now fails the module
  assertion, as does enabling it before the var has been generated.
  Generate with: =clan vars generate <machine> --generator paseo-auth=
  The generator makes a random 32-char URL-safe password; override a chosen
  one with: =printf '%s' 'the-password' | clan vars set <machine> paseo-auth/password=
- Generated and committed for =zeroclaw=.
- Non-clan paseo installations use the legacy sops fallback: the module
  declares =sops.secrets."paseo-auth/password"= from the machine's default
  sops file (nested YAML key =paseo-auth.password=) and renders it into a
  =paseo-env= template. =claude-nixos-config= uses this path; its secret was
  added to =secrets/claude-nixos-config/secrets.yaml=.

* binarin primary group (2026-10-16)
Clan's =users= service only sets =isNormalUser= true, which defaults the
primary group to the shared =users= (gid 100) and leaves the uid locally
allocated — so =services.paseo.group = "binarin"= pointed at a group that
didn't exist. Fixed in nixos-base: =users.groups.binarin= (gid 1000) +
=users.users.binarin.{uid,group}= pinned via
=inventory/users-groups.nix.humanUsers.binarin=. On already-deployed
machines existing files keep group =users= (uid 1000 still owns them);
run =chown -R binarin:binarin /home/binarin= once if the mixed group
ownership ever bothers you.

* Web UI + tailscale serve (2026-10-16)
- =PASEO_WEB_UI_ENABLED=true= via =services.paseo.environment= (env beats
  persisted config; keeps runtime config.json mutations working).
- =services.tailscale.serve.configs.paseo.target = "localhost:6767"=
  serves https://zeroclaw.lynx-lizard.ts.net/ (per-node serve, https on
  :443 by default; module resets+reapplies serves on config change).
- =hostnames = [ "zeroclaw.lynx-lizard.ts.net" ]= lets the serve Host
  header past DNS-rebinding protection (verified locally: allowed Host ->
  200 HTML, other Host -> 403).
- Web UI auth is now declarative and mandatory: clan var =paseo-auth= on
  clan machines, legacy sops =paseo-auth/password= elsewhere; see the
  "Web UI auth via mandatory clan vars" section above.
