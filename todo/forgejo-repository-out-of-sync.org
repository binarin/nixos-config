* DONE Root cause and repair
- User authorized SSH investigation and repair.
- Reflog shows the correct 11:09:46 =push= to =5dff4af= immediately followed
  by =update by push= resetting the branch to =235354d=.
- Push remotes are created by Forgejo 16.0.4 using =git remote add --mirror=,
  which sets =fetch = +refs/*:refs/*=. Git push updates tracking refs using
  that mapping. A mirror push started before a concurrent promotion can
  therefore reset actual source branches to its stale snapshot after finishing.
- Deterministic local Git reproduction confirmed rollback with =--mirror=,
  and preservation with =--mirror=push= (no fetch refspec).
- Confirmed upstream bug: https://codeberg.org/forgejo/forgejo/issues/14273
- Forgejo 17.0.1 already creates remotes using =--mirror=push= and removes
  leftover fetch refspecs before pushing. Its source explicitly links the issue.
  No local package patch or duplicate Nix cleanup is needed.
- Evaluation with a temporary =--override-input common path:../swan-lake-common=
  selects Forgejo 17.0.1. Normal evaluation currently fails because the old
  common lock lacks =overlays.pi-with-extensions= required by existing user edits.
  Neither flake.lock nor unrelated edits were changed; no major upgrade deployed.
- Old nixos-config hook files reference a removed Forgejo 15 store path, but
  recent hook requests succeed and newly created swan-lake-common has no such
  files. Do not assume these legacy files cause this warning on Forgejo 16.
- Initial inspection made no server changes apart from fetching SQLite;
  all database queries were read-only.
