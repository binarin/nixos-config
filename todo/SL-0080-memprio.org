* Design choices
** SL-80 guest oom_score_adj
- Single source: =/usr/local/sbin/pve-oom-priority= (run as =python3 -I=)
  imports the deployed daemon =/usr/local/sbin/pve-memguard= with
  =SourceFileLoader= (the import has no side effects: =mlockall=, the
  writer thread and argv parsing only run from =main()=; bytecode writing
  is off so no =__pycache__= appears in =/usr/local/sbin=). It builds the
  effective config with the daemon's own =Config= from
  =/etc/pve-memguard/config.json= (missing file: =Config({})=). The order
  is not copied anywhere. Tests import the sibling =pve_memguard.py=.
- Mapping: =kill_order= is least important first; =d= = index of the
  default tier, =n_below= = number of tiers after it.
  - tier =i < d=: =round(1000*(d-i)/d)= (first tier +1000)
  - default tier and unlisted guests: 0
  - tier =j > d=: =round(-750*(j-d)/n_below)= (last tier -750)
  - default tier first: no positive values; default last: no negative
    ones; only one tier: everything 0. Python =round()= (ties to even).
  -750 stays above the -900 of the host services and never reaches -1000
  (unkillable): postgres (CT 101) stays killable as a last resort
  (binarin's decision).
  With today's order: 123=1000, 111=667, 116=333, default 0, 124=-150,
  vm109=-300, 112=-450, 115=-600, 101=-750.
- CTs: =lxc.proc.*= keys are not allowed in a pct config, =lxc.include= is.
  =sync= writes =/etc/lxc/oom-priority/<id>.conf= (comment header +
  =lxc.proc.oom_score_adj = N=) for every CT config in =/etc/pve/lxc=,
  listed or not, because a missing include file blocks the CT start. Files
  of removed CTs are left alone. Atomic write (temp file + fsync + rename),
  only when the content differs.
- lxc writes =lxc.proc.oom_score_adj= as host root before the CT init
  execs, so the value is also =oom_score_adj_min= for the whole CT: CT
  processes can raise it, not lower it (EACCES; systemd inside the CT
  ignores that for e.g. udevd's -1000).
- =include <vmid>...= (hand step) adds =lxc.include: /etc/lxc/oom-priority/<id>.conf=
  at the end of the main section, i.e. before the first line starting with
  =[= (snapshot or =[pve:pending]=): a line below a section header belongs
  to that snapshot and is ignored at start. Idempotent; refuses all CTs
  (changes nothing) if any CT config or include file is missing; prints a
  unified diff; holds pve-container's config lock
  (=/run/lock/lxc/pve-config-<id>.lock=) and writes via =<file>.tmp.<pid>=
  + rename like PVE's =file_set_contents= on pmxcfs. Not run by Ansible.
- VMs: hookscript snippet =/var/lib/vz/snippets/oom-priority-hook.sh=
  execs =pve-oom-priority hook <vmid> <phase>=; on =post-start= it writes
  the value to the kvm PID (=/var/run/qemu-server/<id>.pid=, accepted
  only if =/proc/<pid>/cgroup= is the VM's =qemu.slice/<id>.scope=). The
  hook always exits 0 and logs problems to stderr (in the task log), so it
  never breaks a VM start. Only one hookscript per guest: binarin sets it
  by hand after checking none is set. CTs do not use a hookscript (CT 116
  already has =pve-impermanence-hook.pl=).
- =apply= (live, running guests): CT = every PID in =cgroup.procs= under
  =/sys/fs/cgroup/lxc/<id>/= recursively (=lxc.monitor/<id>= is a separate
  tree, not touched); VM = the kvm PID. Per process, emulating a restart
  under the new floor: write the target if the current value is 0 or
  below the target, otherwise keep it (Docker, chromium at 300). A host
  root write also sets that process's =oom_score_adj_min=. Vanished PIDs
  (ENOENT/ESRCH) are skipped.
- =check= (read-only, exit 1 on any problem): include file content,
  include line in each CT's main section, every running guest's processes
  >= target, the CT init (the process with =NSpid= ending in 1) and the
  kvm PID settled per the =apply= rule, VM =hookscript:= equals
  =local:snippets/oom-priority-hook.sh=, and the snippet file is
  executable when VMs exist (a VM whose hookscript file is missing fails
  to start).
- Output: =sync=, =include=, =apply= end with =changed: N= (with
  =--check=: would change); Ansible's =changed_when= compares the last
  line.
** SL-79 ARC cap
- =lineinfile= on =/etc/modprobe.d/zfs.conf= (created if missing, regexp
  =^options zfs zfs_arc_max==) so other options survive; notifies the
  shared =ansible/handlers/update-initramfs.yaml= handler (imported in the
  play's =handlers:=, =update-initramfs -u -k all=; root is on ZFS).
- Live: read =/sys/module/zfs/parameters/zfs_arc_max=; if it differs,
  write the value. In check mode the task runs (=check_mode: false=) as
  =true=, so it reports changed and writes nothing.
- pve-memguard counts ARC above =c_min= as headroom, so the cap lowers its
  headroom figure by whatever the ARC held above 8 GiB.
** SL-82 host OOMScoreAdjust
- Drop-ins =/etc/systemd/system/<unit>.d/50-oom-score-adjust.conf= with
  =[Service] OOMScoreAdjust=-900=, =daemon-reload= when one changed.
  Unit -> value map in =vars/memory.yml= (=pve_host_oom_score_adjust=).
- No restart. Live: for each active unit, write -900 to every PID in its
  =ControlGroup='s =cgroup.procs= whose value differs (check mode: only
  report). Inactive units are skipped. Changed only when something was
  (or in check mode would be) written.
** Ansible
- =playbooks/pve/memory.yml=: =hosts: raum=, tag =memory=,
  =vars/memory.yml=, imports =tasks/zfs-arc.yml=, =tasks/oom-priority.yml=,
  =tasks/host-oom-adjust.yml=. A playbook of its own for the same reason
  as =memguard.yml= (=--tags= on =main.yml= runs the monitoring roles'
  always-tagged checks without facts).
- =tasks/oom-priority.yml=: assert =/usr/local/sbin/pve-memguard= exists,
  install the tool and the snippet, run =sync= then =apply= (=check_mode:
  false= on the command, =--check= passed from =ansible_check_mode=). In
  check mode both are skipped when the tool itself would be installed or
  updated, because the new version is not on the host yet.
- A =kill_order= change through =memguard.yml= alone does not update the
  include files or live values: run =memory.yml= after it.

* Open / risks
- ssh at -900: new ssh sessions (and anything started from them) inherit
  the listener's -900 and its floor, unless sshd restores the original
  value in session children. =qm start= from an ssh shell would start kvm
  at -900; the hookscript (post-start) and =apply= correct that. A
  =pct exec= / =pct enter= process starts with the caller's value, not
  the CT's: =check= reports it if below the target, =apply= fixes it.
- A snapshot rollback restores the snapshot's raw lxc keys and drops the
  include line if the snapshot predates it; =check= reports it, re-run
  =include=.
- Live values from =apply= are only a floor for the processes that exist;
  CT processes forked later inherit from their parents, so that holds.
