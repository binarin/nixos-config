* Goal

Create a new, minimal base module =nixos-base= to replace the current
=baseline= (system) + =binarin-baseline= (user) modules, which have grown too
large and entangled.

Design constraints:
- Clan is **mandatory** (not conditionally loaded like the old =baseline=).
- First iteration must be **absolutely bare**: an empty =binarin= user with no
  config at all, plus SSH access for =root= and =binarin=.
- Guinea pig machine: =xray-exit=.

* Design

** Module structure

Create =modules/nixos-base/default.nix= exporting =self.nixosModules.nixos-base=.

It will contain (first iteration):
1. =clan.inventory.instances.binarin-user= :: same as today (distributed
   service =users=, =roles.default=, user =binarin=, groups =[ "wheel" ]=).
   - This creates the =binarin= user + group via clan's built-in =users=
     service module.
2. =clan.inventory.instances.binarin-admin= :: same as today (distributed
     service =sshd=, =roles.server=, authorizedKeys from secure public keys).
   - This provisions SSH authorized keys via clan's built-in =sshd= service
     module.
3. The =self.nixosModules.nixos-base= NixOS module itself:
   - Imports =self.nixosModules.clan-hostId= and =self.nixosModules.clan-hosts=
     directly (makes clan **mandatory** at the host-config level, without
     pulling in the tailscale OAuth generators that live in =clan-baseline=).
     This is Option A from the clan-baseline split discussion: =clan-baseline=
     stays untouched for the 27 existing =baseline= machines, while =nixos-base=
     only takes the two minimal clan pieces it needs.
   - Does NOT set =hardware.facter.report.system = mkForce false= — that was a
     belt-and-suspenders no-op added in commit 681e3eca. The pinned-pkgs setup
     (via =configured-pkgs= + =_module.args.pkgs=) already makes
     =nixpkgs.hostPlatform= read-only, so facter's own guard short-circuits.
   - Imports =self.nixosModules.sshd= (enables openssh + root authorized keys
     + CA-based principals).
   - Imports =self.nixosModules.inventory= (hostId, =/etc/hosts=, ipAllocation).
   - Imports =self.nixosModules.public-keys= (provides =config.lib.publicKeys=).
   - *Deliberately does NOT import*: emacs, git, interactive-cli, monitored,
     security, sops, tailscale, ci, eternal-terminal, nix, use-nix-cache,
     srvos update-diff, readOnlyPkgs, clan-baseline. Those are out of scope
     for the bare base.

The =binarin= user in the first iteration:
- Created by the clan =users= instance (=binarin-user=).
- Has NO home-manager config (no =home-manager.users.binarin=).
- Has NO shell customization, NO dotfiles.
- SSH authorized keys come from the clan =sshd= =binarin-admin= instance,
  which uses =tags.all= so all machines get the keys.

** What =nixos-base= guarantees (first iteration)

- A working clan core (vars, settings, domain).
- openssh enabled, firewall open on 22.
- root authorized keys (secure, tagged =default=) via =self.nixosModules.sshd=.
- binarin user (uid 1000, group binarin gid 1000, isNormalUser) via clan
  =users= instance.
- binarin SSH authorized keys + principals (=root=, =binarin=) via clan
  =sshd= =binarin-admin= instance.

** What =nixos-base= does NOT include (by design, first iteration)

- No shell (binarin gets the default =bash=).
- No home-manager.
- No sops / secrets wiring.
- No impermanence.
- No nix settings / caches / builders.
- No tailscale, monitoring, security hardening, interactive CLI tools.
- No sudo passwordless config (=security.sudo= belongs to the system baseline,
  not this bare base).

* Closure-size trimming (xray-exit guinea pig)

Measured against the original =baseline=-based xray-exit closure (1400 MiB):

- =clan.core.enableRecommendedDefaults = mkDefault false= in =nixos-base= ::
  removes gitMinimal + dnsutils + tcpdump + curl + jq + htop + nixos-facter
  that clan forces into every machine. ~5 MiB net closure savings (their
  transitive deps — perl, openssl, zlib, curl-libs — are still needed by
  nix/systemd/sops).
- =system.disableInstallerTools = mkDefault true= in =nixos-base= :: removes
  nixos-rebuild-ng (310M), nixos-generate-config (265M), nixos-option (196M),
  nixos-install/enter/build-vms. ~8 MiB net closure savings for the same
  reason (nix + python3 + perl remain for nix-daemon / activation).
- Combined: 1400 → 1323 MiB. =system-path= alone went 823 → 644 MiB.
- Remaining ~1.3 GiB floor is nix + systemd + dbus-broker + perl/python that
  any NixOS machine with =nix-daemon= carries. Further cuts require disabling
  =nix.enable= (not viable for a real machine) or shrinking nixpkgs itself.
- **Iteration 2**: imported nixpkgs =(modulesPath + "/profiles/minimal.nix")=
  and =(modulesPath + "/profiles/perlless.nix")= into =nixos-base=.
  =perlless= replaces perl-based activation with =boot.initrd.systemd.enable=,
  =system.etc.overlay.enable=, =services.userborn.enable= and sets
  =forbiddenDependenciesRegexes = [ "perl" ]=. Result:
  xray-exit 1323 → 1203 MiB, perl fully gone, =system-path= 644 → 453 MiB.
- **Floor comparison** (same pinned nixpkgs 21ea275):
  | pure nixpkgs profiles/minimal.nix | 1187 MiB | floor       |
  | xray-exit (nixos-base + extras)   | 1203 MiB | +16 MiB     |
  | original baseline xray-exit       | 1400 MiB | +213 MiB    |
  Our full stack (clan + sops + xray + disko + qemu-guest + binarin + sshd)
  adds only 16 MiB over the bare nixpkgs floor. The remaining ~1.2 GiB is the
  irreducible nix-daemon + systemd cost; only =profiles/image-based-appliance=
  (=nix.enable = false=) goes below it, at the cost of no in-place rebuilds.
- Considered but rejected for =nixos-base=: the nuclear "~100 KiB" sidecar
  profile (fake =boot.isContainer=, stubbed =systemd.package=, no kernel/initrd,
  =system.activatable = false=). It targets non-NixOS hosts (system-manager /
  containers), not bootable machines — would produce an unbootable xray-exit.

* Risks / open questions

1. *Dangling overrides in xray-exit.nix*: =services.tailscale.enable =
   lib.mkForce false= and =nixos-config.export-metrics.enable = false= — these
   options were defined by modules pulled in by the old =baseline= (=tailscale=,
   =monitored=). With =nixos-base= they won't exist → these lines will error.
   :: *Resolution*: remove these two override lines from =xray-exit.nix= in this
   iteration (tailscale and metrics simply won't be present).

2. *clan openssh generator / =programs.ssh.knownHosts = lib.mkForce {}=* hack
   in =xray-exit.nix= — referenced =XXX= comment about =binarin-admin= sshd.
   Keep it for now; verify it still evaluates with =nixos-base=.

3. *srvos update-diff removed*: old baseline imported
   ="${inputs.srvos}/nixos/common/update-diff.nix"=. =nixos-base= drops it.
   Deploy diffing on xray-exit will be lost unless re-added later. Acceptable
   for the bare base.

4. *Is =self.nixosModules.inventory= needed explicitly?* The old =baseline=
   imported it. =clan-baseline= imports =clan-hosts= / =clan-hostId= but not
   =inventory= (=ipAllocation= / =networking.hosts=). xray-exit uses
   =flakeConfig.inventory.ipAllocation= at the flake-parts level (fine) but the
   NixOS =networking.hosts= from inventory is used elsewhere. Include
   =self.nixosModules.inventory= in =nixos-base= to keep host resolution working.
5. *clan-baseline split (Option A)*: =nixos-base= imports =clan-hostId= +
   =clan-hosts= directly rather than =clan-baseline=, so the tailscale-admin /
   tailscale-auth OAuth generators are not pulled into the bare base.
   =clan-baseline= itself is left untouched. RESOLVED.
